## 🆕 v2.5 更新：三个关键问题修复

### ① AI 大模型获取不到（已修）

**根因**：插件用了 `context.get_using_provider_async()`，但这个 **async 方法是 AstrBot 4.29+ 才引入的**。
你的 **4.27.2 只有同步版 `get_using_provider()`**，导致 `AttributeError` 被 `except` 吞掉，
表现就是「AI 页显示未检测到可用模型」「生成了但没内容」。

**修复**：新增 `_resolve_provider()` 兼容层，自动探测：
1. 先试 async 版（4.29+）
2. 回退同步版（4.26~4.28）
3. 再回退直接读 `provider_manager`

`_all_providers()` 同样做了多路径兼容（`get_all_providers()` → `provider_insts` → `providers` → `insts` → `inst_map`）。
现在 **4.26 ~ 4.29+ 全版本都能正确读出你的模型列表**。

### ② 群聊不能自助加载，只能群内发指令（已修）

**新增「群管理 → 扫描并绑定群」**：点一下按钮自动拉取机器人所在的所有 QQ 群，
勾选后一键绑定 / 解绑，**完全不需要在群里发指令**。

数据源三路合并，任何一路可用都能扫到：
1. OneBot `get_group_list`（最准，含全部群 + 群名 + 人数）
2. 插件记录的历史可见群（收到过消息的群自动记录，即使未绑定）
3. 已绑定群（补进列表，避免人工命名的群名被覆盖）

### ③ 不能覆盖升级，必须先卸载（正确升级流程）

**这是 AstrBot 平台机制**（`star_manager.py` 检测同名目录直接抛异常），不是插件 bug。
**用 WebUI 三步升级即可，运营数据不会丢**——已对照 4.27.2 源码逐行核实：

```
① WebUI → 插件管理 → 找到本插件 → 卸载
   ⚠️ 卸载确认弹窗里有两个勾选框（删除配置 / 删除数据），
      保持默认【都不勾】，直接确认。
② 上传新的 astrbot_plugin_wzry_group_ops.zip 安装
③ 重启 AstrBot（或直接刷新插件列表）
```

**为什么数据不会丢？** 插件的运营数据存在：
```
data/plugin_data/astrbot_plugin_wzry_group_ops/data.json   ← 数据在这里（卸载不动它）
data/plugins/astrbot_plugin_wzry_group_ops/                ← 插件代码在这里（卸载只删这个）
```
两个目录完全分离。AstrBot 的卸载逻辑 `delete_data` 参数**默认 False**，只有你手动勾选「同时删除数据」才会删 `plugin_data`。

若你的 AstrBot 部署在本机 Windows 且能直接访问文件夹，也可以用随包的 `一键升级插件.bat`（自动备份 + 替换）。服务器/Docker 环境直接用上面的 WebUI 三步即可。

## 🆕 v2.4 更新：修复「装上后看不到 WebUI」

**如果你装完插件、在插件详情页里找不到「运营作战台」入口 —— 这个版本已修复。**

**根因**（对照 AstrBot 各版本源码逐行确认）：不同 AstrBot 版本扫描的视图目录名和 bridge 全局名**不一样**：

| AstrBot 版本 | 视图目录 | bridge 全局名 |
|---|---|---|
| v4.26 ~ v4.28（含你的 4.27.2） | **只认 `pages/`** | `AstrBotPluginPage` |
| v4.29+ | `views/` 优先，`pages/` 兼容 | `AstrBotPluginView` |

旧版本插件只放了 `views/` 目录、且前端只读 `AstrBotPluginView` → **在 4.27.2 上视图既不被扫描到、bridge 也取不到**，所以完全看不到作战台。

**修复方式（全版本通吃）：**

- 同时提供 `pages/` 与 `views/` 两个视图目录，内容完全一致
- 前端同时兼容两个 bridge 全局名：`window.AstrBotPluginView || window.AstrBotPluginPage`
- HTML 里显式引入 bridge SDK，不依赖注入时序
- i18n 同时提供 `pages.dashboard.*` 与 `views.dashboard.*` 两套键

装完后打开位置：**WebUI → 插件管理 → 找到「王者荣耀私域运营助手」→ 点进插件详情页 → 在组件列表里点「运营作战台」**。

## 🆕 v2.2 更新：修复 WebUI 开关点不动

**现象**：群管理页的「群总开关」点击无反应（或点了立刻弹回）。

**根因**（用真实浏览器实测定位）：

1. `.toggle input` 被设成 `width:0; height:0; opacity:0`，点击完全依赖 `<label>` 的隐式转发。
   在 AstrBot 的受限 iframe / 部分 WebView 里这种转发不可靠 —— 点上去没有命中 input。
2. 每次切换后调用 `loadGroups()` **整表重渲染**，节点被替换，视觉上像"点了没反应"。
3. 原代码不读取服务端返回值，一旦请求失败或延迟，UI 与真实状态不一致。

**修复**：

| 改动 | 说明 |
|------|------|
| `input` 铺满开关区域 | `position:absolute; inset:0; width/height:100%; z-index:2` —— 点击任意位置都直接命中 input，不再依赖 label 转发 |
| 改为原地更新 | 切换后只更新该卡片的状态与样式，不再整表重渲染（不闪烁、不丢滚动位置） |
| 以服务端返回为准 | 用响应里的 `enabled` / `features` 回写 UI，彻底消除"回弹" |
| 总开关联动 | 关闭某群总开关时，其单项功能开关自动置灰禁用 |
| `alert()` → 页内 toast | 视图在受限 iframe 中，原生 `alert` 可能被拦截导致"无反馈"错觉 |
| 自动化页开关同步优化 | 同样改为原地更新 + 状态提示，保持一致体验 |

> 另外修正了页脚版本号（原仍显示 v1.0.0）。

- WebUI「群管理」页编辑 + 实时预览

- 占位符：`{nickname}` `{group_no}` `{date}`

**3. 修复的缺陷**

| # | 问题 | 影响 |

| 8 | 冷场救场要求有消息记录 | 新绑群要等首条消息才触发 |
| 9 | 参数无范围校验 | 可存入非法值 |

1. 把 `astrbot_plugin_wzry_group_ops` 整个文件夹放到 AstrBot 的 `data/plugins/` 目录下。
2. 打开 AstrBot WebUI → **插件管理** → 点击刷新。
3. 找到「王者荣耀私域运营助手」并启用。
4. 在插件卡片上点击进入插件详情，即可打开 **自动化运营引擎** 可视化视图。

## 🧠 运营方法论

本插件的设计基于游戏社群的私域逻辑：

**群对用户的三个价值**：开黑搭子 / 交友扩列 / 段位互助。
用户进群的核心诉求是「找人一起玩」，所有运营动作围绕这个诉求供给价值。

**增长飞轮**：

```
公域引流 → 进群欢迎+身份卡 → 当晚开黑车队 → 积分激励 → 晒战绩+拉人返利 → 老带新裂变
```

关键：**进群当天必须体验到一次开黑**，留存率翻倍。
v2 的「自动新人跟进」就是为此设计——30 分钟没冒泡就自动引导。

**拉新三阶段**：

| 阶段 | 人数 | 核心动作 |
|------|------|----------|
| 种子期 | 0→50 | 拉熟人、定群规、每晚固定开黑、选出 5 个车队骨干 |
| 内容期 | 50→300 | 抖音/小红书/贴吧发内容、每日 SOP、交友专场 |
| 裂变期 | 300+ | 邀请返利、组队拉人、拉新排行榜、积分兑换日 |

**积分体系**是游戏群替代电商「复购」的留存引擎——v2 让它自动运转，
成员只要发言就自动攒分，不需要他们记得发命令。

## 🛡️ 风控红线

- **主动打扰克制**：冷场救场与沉睡唤醒仅在活跃时段（默认 9:00-23:00）执行
- **防刷屏**：救场有冷却、唤醒有冷却与数量上限、关键词应答有冷却
- **拉人频率**：分批、隔天，避免账号被判定骚扰
- **广告治理**：设管理员 + 关键词过滤，及时踢发广告的
- **诈骗防范**：禁止「代充/低价点券/皮肤返利」，99% 是诈骗
- **未成年人**：不引导充值、不组织涉金钱赌博活动
- **隐私保护**：不索取真实姓名/身份证/手机号

## ❓ 常见问题

**Q：怎么绑定群？一定要在群里发指令吗？**
不需要。**WebUI → 群管理 → 点「扫描群列表」** → 勾选 → 「绑定选中」即可。
（群内 `/运营 绑定` 仍然可用，两种方式等价。）

**Q：升级时提示「安装失败：目录 xxx 已存在」？**
AstrBot 不允许覆盖安装同名插件（平台机制）。正确升级姿势（数据不丢）：
1. 插件管理 → 卸载本插件（弹窗里**不要勾选**「删除配置/删除数据」，保持默认）
2. 上传新 zip 安装
3. 重启 AstrBot 或刷新插件列表
运营数据存在 `data/plugin_data/` 下，卸载默认不删，升级后自动衔接。

**Q：AI 页显示「未检测到可用模型」？**
v2.5 已修复 4.27.x 的兼容问题。若仍显示：
1. 确认 AstrBot 里已配置至少一个对话模型（服务提供商 → 新增）
2. 确认该模型已设为「默认对话模型」
3. 到本插件 WebUI 的「AI 话术」页点「刷新」重新探测

**Q：装完插件看不到「运营作战台」入口？**
1. 确认打开位置正确：**WebUI → 插件管理 → 点进插件详情页**（不是列表卡片上），在下方组件列表里找「运营作战台」。
2. 确认插件已**启用**（未启用的插件不显示视图）。
3. 如果是**覆盖安装/更新**，请先卸载旧版、重启 AstrBot 再装 —— 目录结构有变化时热重载可能读不到。
4. 若仍看不到，看 AstrBot 日志里有没有本插件的加载报错，把日志发我。

**Q：AI 话术需要我自己填 API Key 吗？**
不需要。插件直接复用 AstrBot 已配置的对话模型。
只要 AstrBot 里有一个能用的模型，「AI 话术」页就会显示模型名并可直接使用。

**Q：AI 生成失败 / 没反应？**
说明模型不可用（未配置 / 超时 / 被限流）。此时插件会**自动降级用内置模板**，运营不会中断。
可到「AI 话术」页查看模型状态徽标：显示"未检测到可用模型"就去 AstrBot 的模型配置里加一个。

**Q：开了 AI 会不会乱发、发奇怪内容？**
有三重约束：① 可编辑的**人设**与**硬性约束**每次都会附加给模型；
② 模型输出会自动清洗（去 markdown / 引号 / 口头前缀）；
③ 生成的只是**草稿**，必须你点「采纳」或发 `/运营 采纳` 才会正式生效。

**Q：AI 会花很多钱吗？**
总开关默认关闭。开启后按需调用（生成/润色是你手动点的；救场和应答兜底有冷却时间）。
可随时关掉总开关，立刻回到纯模板模式。

**Q：绑定后需要我做什么吗？**
不需要。引擎自动运转。你只需偶尔看作战台调整参数。

**Q：怎么只运营一个群，不让所有群都触发？**
两种方式：① WebUI 作战台 →「群管理」页，把其它群的总开关关掉；
② 在对应群里发 `/运营 关闭`。关掉后该群不再收到任何自动消息。

**Q：不想让某个群被"沉睡唤醒"打扰，但其它功能保留？**
`/运营 功能 wake off`（或去「群管理」页关掉该群的"沉睡唤醒"）。

**Q：入群欢迎词怎么改？**
WebUI「群管理」页编辑，或群内 `/运营 欢迎词 <新内容>`。
支持占位符 `{nickname}` `{group_no}` `{date}`。

**Q：视图没出现？**
确认 `views/dashboard/index.html` 存在、插件已启用，并在插件详情页刷新。

**Q：数据采集不到？**
自动化采集依赖 `get_group_member_list` 接口，需要 `aiocqhttp` 适配器。
QQ 官方 API 平台不支持。可在作战台点「采集群数据」手动触发验证。

**Q：推送没发出去？**
依次检查：① 群已绑定（`/运营 绑定`）；② 该群总开关是开的（`/运营 状态`）；
③ 使用了 `aiocqhttp`（NapCat 等）适配器。

**Q：定时任务时间不准 / 会漏发吗？**
引擎每 30 秒轮询一次。若某次 tick 因任务耗时延迟过了设定时间点，
系统会自动补发（不会漏发），且同一天不会重复发送（去重标记已持久化）。

**Q：从旧版本升级，数据会丢吗？**
不会。首次加载旧 `data.json` 时会自动补齐 `enabled` / `features` / `welcome_text`
等新字段，原有群绑定、积分、运营数据、推送计划全部保留。旧群默认视为"启用"。

**Q：数据存在哪？**
`data/plugin_data/astrbot_plugin_wzry_group_ops/data.json`，重装插件不丢失。
